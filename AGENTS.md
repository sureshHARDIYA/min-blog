# Repository agent instructions

These rules apply to all AI coding, editorial, research, and publishing agents working on this repository.

## Article audio compatibility — mandatory

Every new or materially edited article in `src/content/blog/*.md` MUST be suitable for both visual reading and the Google Chirp 3 HD Listen experience (audio hosted in Cloudflare R2). Before committing an article:

1. Write an excellent standalone visual article first. Keep clear `##` sections and meaningful `###` subheadings. Preserve real citations and links; never fabricate evidence, statistics, sources, or audio descriptions.
2. Write natural spoken-friendly sentences and pronounceable terminology. Introduce abbreviations at first use, avoid raw URLs in prose, and never rely on a chart, screenshot, code block, or table alone to communicate the central conclusion.
3. For **tables**, provide a concise adjacent interpretation supported by the actual rows. Avoid duplicating every cell in spoken narration for large tables. For **charts**, explain what is measured, units, scope/time window, important values and defensible takeaway. Validate every numerical statement against source data.
4. For **images and diagrams**, provide useful Markdown alt text and, where needed, an accurate narrated description. For **video/audio embeds**, state their purpose; do not claim the player narrates their contents. For **code**, explain intent and security implications rather than reading syntax character by character.
5. Maintain author-reviewed narration overrides in `src/content/narration/<slug>.json` for media that cannot be accurately represented by the deterministic Markdown extractor. The format is described at the top of `scripts/narration.py`. The section keys are zero-based indexes of blocks split on `##`; arrays index media occurrences within each section.
6. **Custom React charts/components are not automatically interpreted** by the Markdown narrator. Supply explicit prose in the article, an accurate narration override if the content is represented in the Markdown stream, and/or an implemented chart-to-narration mapping. Never pretend automatic visual interpretation exists.
7. Run `python3 scripts/check-article-narration.py` and review warnings before publishing. For every newly authored rich-media section, confirm a reader listening without the screen understands the important point.
   Norwegian articles must declare `lang: nb` in the frontmatter so they are narrated with the Norwegian voice; articles without it are narrated in English.
8. Never call a generative model at playback time or synthesize on every request. Audio is pre-generated by GitHub Actions, stored in R2, and linked through versioned manifests. Keep secrets out of articles, client bundles, manifests, and logs.
9. Regenerate audio only after editorial review and cloud configuration; do not merge or publish unverified generated audio. Keep visual content available even when audio is missing or stale.

## Definition of done for article PRs

- [ ] The article is accurate, sourced, accessible, and organized with sensible headings.
- [ ] Tables, charts, diagrams, videos, and code have understandable spoken context.
- [ ] Narration overrides (if required) are reviewed against the real content/data.
- [ ] Narration validation has run and warnings have been resolved or documented.
- [ ] The build and applicable CI checks pass.
- [ ] No API keys, storage credentials, or invented evidence were introduced.

If narration is not yet configured for the environment, do not block publication of the visual article; explicitly note that Listen audio is pending.
